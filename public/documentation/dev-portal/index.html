Dev Portal public/northeastern/dev.html

A single self-contained HTML file (~2,400 lines) that lives at public/northeastern/dev.html. It gives you full visibility into the course database from the public GitHub Pages URL, and write access to it locally. That distinction — read-only on HTTPS, full Trigger access on localhost — governs everything about how the portal behaves.

Local vs. remote — the governing split

On load, the portal checks ["localhost","127.0.0.1",""].includes(location.hostname). This single boolean determines almost every UI decision:

flowchart LR subgraph Local["localhost — full access"] direction TB L1["No auth required"] L2["Trigger tab: all 4 adapters available\nReview & Push"] L3["Log tab: ⏳ Pending push badge\nfor entries not yet on GitHub Pages"] end subgraph Remote["GitHub Pages — read-only"] direction TB R1["Auth required (PBKDF2 hash check)"] R2["Trigger tab hidden\n(HTTPS → HTTP mixed-content blocked)"] R3["Log tab shows deployed history only"] end

The Trigger tab is hidden on HTTPS because it sends requests to http://localhost:3333. Browsers block cross-origin HTTP requests from HTTPS pages as mixed content. The portal detects this at load time and hides the Trigger tab entirely rather than showing buttons that would silently fail.

Auth system (remote only)

The password is never stored in plain text. Run npm run dev:pw to generate a PBKDF2-SHA256 hash (300,000 iterations, Web Crypto API) and embed it in dev.html. At login, the browser hashes the entered password and compares hex strings — no server involved. On success, the session token is written to sessionStorage (not localStorage), so it clears when the tab closes. A shared machine cannot be left permanently unlocked.

Backend server — catalog-check-server.js

catalog-check-server.js is started alongside Vite by npm run dev. It listens on :3333 and provides four endpoints that the Trigger tab calls:

EndpointWhat it does
GET /adaptersReturns the list of available adapter definitions (id, label, command).
GET /run?id=<id>&write=<0|1>Spawns the adapter script as a child process and streams stdout/stderr as SSE events. write=1 means the script is passed --write. On exit, appends a manual-trigger entry to change-log.json.
GET /git-statusReturns {dirty, status, diff} showing which tracked data files have uncommitted changes.
POST /git-pushRuns git commit && git push origin main on the tracked data files. This is the "Review & Push" action.

Tracked data files for git operations: all-courses.json, catalog-courses.json, change-log.json, scrape-state.json, src/core/dataMeta.json, public/data-meta.json, src/data/majors/, data/northeastern/.
