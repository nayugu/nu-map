Log tab 📋 change-log.json

A paginated audit log of every data operation that has modified the course database. Reads public/northeastern/change-log.json directly. On localhost, it also fetches the deployed version of that file from GitHub Pages and computes which local entries haven't been pushed yet — those get a ⏳ Pending push badge.

Source file
public/northeastern/change-log.json
Max entries
600 (oldest are dropped when the limit is exceeded)
Available on
Both localhost and GitHub Pages (read-only)

Pending push badge

On localhost, the Log tab fetches the deployed change-log.json from GitHub Pages at load time and builds a Set of timestamps that are already on the remote. Any local entry whose timestamp is not in that Set gets the amber ⏳ Pending push badge. This tells you at a glance which runs still need to be pushed via Review & Push.

Entry types

typeCreated byKey fields shown
manual-triggerTrigger tab — ⚡ Run locally (any adapter)adapter label, exit code (✓ Exit 0 / ✗ Exit N)
availabilityscrape-availability.js --writecovered / total courses with history; terms queried
majorsscrape-majors.js --writescraped / written / skipped / failed program count
nupath-auto-updatefetch-nupath.js --write (via Trigger tab or GitHub Actions)scanned / changed / gained-only / lost-only; source (Tableau or catalog); triggeredBy; GH Actions runId
no type fieldscrape-catalog.js --rotate --writesubject code (e.g. "CS"); added[] / modified[] (per-field before→after) / removedFromCatalog[]

Legacy entry types (nupath-scan, nupath-manual-fix) from the old portal are still rendered if they appear in the log file — they show NUPath discrepancy stats and apply-fix counts respectively.

change-log.json format

{
  "runs": [
    {
      "type": "manual-trigger",
      "subject": "Course Catalog (manual)",
      "adapter": "catalog",
      "timestamp": "2026-05-19T14:32:00.000Z",
      "exitCode": 0
    },
    {
      "type": "availability",
      "subject": "📅 Term Availability",
      "timestamp": "2026-05-19T12:00:00.000Z",
      "terms": ["202310","202330","202340","202360", ...],
      "covered": 4812,
      "total": 5200
    },
    {
      "timestamp": "2026-05-18T10:00:00.000Z",
      "subject": "CS",
      "added": [],
      "modified": [{"code":"CS 3500","changes":[{"field":"description","before":"...","after":"..."}]}],
      "removedFromCatalog": [],
      "unchanged": 87
    }
  ]
}

Entries are prepended (newest first). The 600-entry cap is enforced by every script that writes to the log.
