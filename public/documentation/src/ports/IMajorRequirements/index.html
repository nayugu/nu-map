IMajorRequirements program loading & audit

The adapter that knows where to find major/minor definitions and how to audit them against a plan. Exposes option lists for the search dropdowns, raw JSON loaders for GradPanel, and (once implemented) a full audit pipeline. All program-list and loading logic lives here — not in the UI.

Port key
"majorRequirements"
Consumed by
GradPanel (option dropdowns + loadMajor()/loadMinor()), future AI assistant audit path
Vite constraint
import.meta.glob() requires string literals — glob patterns stay in the loader files, not here

Contract — methods

MethodReturnsPurpose
getMajorOptions()ProgramOption[]Flat list of all available major options. Used when searching without grouping.
getMinorOptions()ProgramOption[]Flat list of all available minor/certificate options.
getMajorOptionGroups()Map<string, ProgramOption[]>Majors grouped for the search dropdown. Keys are group labels (e.g. "2025 — Khoury College"); values are option arrays.
getMinorOptionGroups()Map<string, ProgramOption[]>Same as getMajorOptionGroups() but for minors.
loadMajor(path)Promise<object>Fetch the raw program definition JSON for a given option id/path. The returned shape is adapter-specific; GradPanel passes it through gradRequirements.js.
loadMinor(path)Promise<object>Same as loadMajor() but for a minor.
auditMajor(id, plan, courseMap)Promise<Program>Load a major by id and audit its requirements against the given plan. Returns the Program with the requirement tree fully populated. Not yet implemented in the NU adapter — currently throws.
auditMinor(id, plan, courseMap)Promise<Program>Same as auditMajor() but for a minor. Not yet implemented in the NU adapter.
getSources()SourceInfo[]External data sources. See IAttributable.
ℹ
auditMajor / auditMinor are Stage 2: GradPanel currently calls loadMajor() and then runs gradRequirements.js directly (client-side). The auditMajor()/auditMinor() methods exist in the port interface for future server-side or AI-driven auditing but throw Error("not yet implemented") in the NU adapter.

Northeastern reference implementation

The NU adapter wraps majorLoader.js / minorLoader.js which own the import.meta.glob() calls (a Vite build-time constraint requiring string literals at the call site). Two adapter-internal helper functions do the name parsing:

  • fmtLabel(folderName) — strips the campus location tag and title-cases the result: "computer_science_(boston)" → "Computer Science". Short all-lowercase words (≤3 chars) like "bs", "cs" are uppercased as acronyms.
  • fmtLocation(folderName) — extracts the location tag: "computer_science_(boston)" → "Boston". Returns "" if no tag.

These helpers are passed as a parameter to getMajorOptions(majorRequirements) inside the loader — they are not part of the port interface.

Generic default

Delegates to the same loader files with identity functions for fmtLabel (no transformation) and fmtLocation (always returns ""). This works for any folder naming convention that doesn't need custom parsing.

✦
The generic default works fine if your major data uses clean folder names with no embedded metadata. Only override if your folder names have location tags, special characters, or other institution-specific patterns that need stripping before display.
