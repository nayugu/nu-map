northeastern/ Reference implementation

Northeastern University's full adapter — every institution-specific value and rule in one folder. Nine files, one per driven port, plus a bundle export. This is the reference implementation to copy when forking for a new school. No file outside this folder may contain NU-specific logic.

Data source history

The northeastern adapter went through a deliberate migration from external dependencies to self-owned data. The original approach used external git submodules to bootstrap quickly; over time each was replaced with our own scrapers for stability and control.

DataOriginal sourceCurrent sourceStatus
Course metadata external/nu-courses submodule → husker.vercel.app API scripts/scrape-catalog.js → public/northeastern/catalog-courses.json Migrated
Term availability external/searchneu submodule (SearchNEU) scripts/scrape-availability.js → public/northeastern/term-history.json Migrated
Major requirements external/graduatenu submodule (sandboxnu/graduatenu) scripts/scrape-majors.js → src/data/majors/ (scraped wins; submodule is fallback) In progress
Minor requirements external/graduatenu submodule Not yet migrated — still from submodule Pending
✦
Why we migrated: external submodules gave us a fast start but no control — schema changes, outages, or stale data in those repos would silently break the app. Own scrapers let us control the update cadence, validate output, and apply patches via data/patches/. The goal is to remove all external submodules once minor scraping is complete.

calendar.js — semester types and Banner decoding

Four semester types, each with a weight that drives all span arithmetic. A work term occupies a slot when termWeight > semWeight — the code never hardcodes duration comparisons.

idlabelweightoptionalBanner suffix
fallFall1.0false10
springSpring1.0false30 (32 = Law Spring → spring)
sumASummer 10.5true40 (52 = Law Summer → sumA)
sumBSummer 20.5true60

Spring uses idPrefix "spr" (not "spring") for backward-compatibility with existing localStorage plan keys. Banner codes 32 (Law Spring) and 52 (Law Summer) are remapped to the standard spring/sumA types.

specialTerms.js — co-op and internship

Two term types reflecting NU's co-op program and optional internship policy. The weight field matches ICalendar's semester weights so the span logic works uniformly:

getCoverage(placements, courseMap, grantedAttrs) unions course.attributes for all placed courses, then adds the codes in grantedAttrs. grantedAttrs is computed by computeGrantedAttrs() in specialTermUtils.js — it collects the NUPath grants from all placed work terms (co-ops grant EX).

courseCatalog.js — data pipeline

The NU adapter owns the entire course data fetch-and-normalize pipeline. PlannerContext calls fetchAll() once at startup and receives a normalized Course[]:

  1. Fetch public/northeastern/catalog-courses.json — the scraped catalog with course metadata, attributes, and prereq trees.
  2. Fetch public/northeastern/term-history.json — Banner term availability per course per semester. Merge into each course's termHistory object.
  3. Call deriveTerms() on each course — produces a terms set (the predicted offering semesters) from term history using a P≥0.5 threshold: if a course was offered in at least half of the scraped instances of a given semester type, it is considered offered in that type.

index.js — bundle export

northeastern/index.js imports all 9 adapter files (including aiAssistant) and exports them as a typed overrides object. src/config.js currently imports each file individually for selective overriding, but northeastern/index.js provides the same bundle for contexts where you want the full NU adapter as one import:

// src/adapters/northeastern/index.js — bundle export
const overrides = {
  institution, calendar, creditSystem,
  attributeSystem, specialTerms, majorRequirements,
  courseCatalog, localization, aiAssistant,
};
export default overrides;
// src/config.js — individual imports for selective overriding
import { wire }          from './adapters/wire.js';
import institution       from './adapters/northeastern/institution.js';
import calendar          from './adapters/northeastern/calendar.js';
// ... 5 more imports
// import aiAssistant from './adapters/northeastern/aiAssistant.js'; // disabled until hosted

export const institutionAdapter = wire({
  institution, calendar, creditSystem,
  attributeSystem, specialTerms, majorRequirements,
  courseCatalog, localization,
  // aiAssistant,  ← re-enable once VITE_MCP_SERVER_URL points at a live server
});

Forking for a new institution

The northeastern folder is the starting point for any fork:

  1. Copy src/adapters/northeastern/ to src/adapters/myuniversity/.
  2. Edit each file. Only institution.js and courseCatalog.js are required changes — everything else can stay as-is if the institution has a similar structure. Omit files entirely to fall back to the generic defaults.
  3. Update the 8 import lines in src/config.js to point at your new folder.
File to changeWhy / what to change
institution.jsid, name, storagePrefix, portal/audit system names — always required
courseCatalog.jsURL to your course JSON, fetch strategy, normalization logic — always required
calendar.jsOnly if semester structure differs (e.g. quarters, trimester, no summers)
creditSystem.jsOnly if unit name or standard credit value differs
attributeSystem.jsReplace NUPath grid with your institution's gen-ed framework, or use generic (empty grid)
specialTerms.jsOnly if co-op/exchange programs exist. Use generic (empty types) if not.
majorRequirements.jsOnly if your major data folder naming differs from _(location) suffix pattern
localization.jsReplace NU-specific portal/system names in disclaimer bullets
aiAssistant.jsWire a no-op stub if you have no MCP server; omit for generic default (always unavailable)
✦
Invariant to check: After forking, verify that src/ui/ contains zero direct imports from your adapter folder. All institution config must flow through usePort(). Run: grep -r "adapters/" src/ui/ — should return nothing.
