data/ I/O layer

Three thin I/O modules. No business logic, no React, no adapter imports. Each wraps one type of external resource: major/minor requirement JSON files (via Vite lazy imports) and browser localStorage. Course loading belongs entirely to the ICourseCatalog adapter — there is no courseLoader module here.

Invariant
Zero imports from src/adapters/ or React. Path-parsing helpers come from the IMajorRequirements port passed as a parameter.

majorLoader.js

Major requirement JSONs come from two sources, merged at module load time. Scraped entries take precedence on path collision:

// Two separate glob calls (Vite requires static string literals)
const _externalMap = import.meta.glob(
  '../../external/graduatenu/packages/api/src/major/majors/**/parsed.initial.json',
  { eager: false }
);
const _scrapedMap = import.meta.glob(
  './majors/**/parsed.initial.json',
  { eager: false }
);

// Scraped wins: same path suffix → scrapedMap entry replaces externalMap entry
const _moduleMap = { ..._externalMap, ..._scrapedMap };

All ~1,400+ path stubs are registered at build time by Vite, but the actual JSON is never loaded until a specific major is selected. loadMajor(path) calls the stub function lazily — only one JSON is ever in memory at a time.

FunctionPurpose
getMajorOptions(majorRequirements)Return all available majors as { path, year, college, collegeLabel, folder, label, location }[]. No JSON loaded — parses paths only. Sorted newest year first, then by college, then by label. Cached by majorRequirements identity.
getMajorOptionGroups(majorRequirements)Group getMajorOptions() output by "YYYY — College Label" for <optgroup> rendering in GradPanel. Returns an ordered Map<groupKey, options[]>.
loadMajor(path)Async — lazily loads and returns the Major2 JSON for a given path. Calls canonicalizeMajorPath() first to handle legacy paths from before the external/ submodule reorganization.
canonicalizeMajorPath(path)Migrates old paths from before the submodule move. If the path isn't in the registry, tries replacing the old prefix ../../graduatenu/ with ../../external/graduatenu/.

Why two sources? The external/graduatenu/ submodule is the upstream legacy data — 1,400+ major files scraped by the GraduateNU team. The src/data/majors/ folder contains our own scraped overrides for years or programs where the upstream data is out of date. The merger means we get broad coverage from upstream while maintaining accurate overrides for the programs we care most about.

minorLoader.js

Identical architecture to majorLoader, but uses only the external/graduatenu source (pointing at the minor/minors/ tree). There is no scraped minor override folder currently. Exports getMinorOptions(), getMinorOptionGroups(), loadMinor(), canonicalizeMinorPath().

persistence.js

All plan state lives in one localStorage key, namespaced by institution.storagePrefix. The key format is {prefix}-state-v2 — the -v2 suffix is a schema version that allows breaking state changes to be handled cleanly (old keys are simply ignored).

FunctionPurpose
storageKey(prefix)Returns `${prefix}-state-v2`. Exported so Header can clear the key directly without importing the full module.
loadSaved(prefix)Reads and JSON-parses the saved state. Returns null if no saved state exists or if JSON is malformed.
saveState(prefix, persist, obj)Writes the plan state. When persist=false, writes {persist:false} only — a marker that tells the next load not to restore any plan state. Silently swallows quota-exceeded errors.
clearState(prefix)Removes the key from localStorage entirely (full reset).

Multiple institution forks can run in the same browser without collision because each uses a different storagePrefix (NU uses "ncp"). The generic default uses "map".

Full startup data flow

sequenceDiagram participant PC as PlannerContext participant PS as persistence.js participant CC as courseCatalog adapter participant ML as majorLoader.js participant LS as localStorage participant FS as public/northeastern/ (static) participant EXT as external/graduatenu/ (Vite stubs) participant SCR as src/data/majors/ (Vite stubs) PC->>PS: loadSaved(storagePrefix) PS->>LS: read {prefix}-state-v2 LS-->>PS: saved JSON or null PS-->>PC: hydrated state (or defaults) PC->>CC: courseCatalog.fetchAll() CC->>FS: fetch catalog-courses.json + term-history.json FS-->>CC: course catalog + Banner term history CC-->>PC: Course[] (normalized, termHistory merged) Note over PC: User selects major in GradPanel PC->>ML: loadMajor(path) ML->>EXT: lazy-import parsed.initial.json ML->>SCR: (wins if scraped version exists) ML-->>PC: Major2 requirement tree Note over PC: Any state mutation PC->>PS: saveState(prefix, persist, planObj) PS->>LS: write {prefix}-state-v2
Course loading is fully owned by the adapter — persistence.js and majorLoader.js never touch course data. Major JSONs are loaded on first selection and are not cached across sessions.
