prereqEval.js Core logic

Evaluates whether a course's prerequisites are satisfied given the current placement state. Returns not just pass/fail but why it fails: missing entirely, or placed in the wrong order.

Parent
core/
Called by
PlannerContext.jsx (for every placed course, on every state change)
Result feeds
prereqViolations Map → CourseCard warning icons, RelationLines SVG

evalPrereqTree algorithm

flowchart TD A["evalPrereqTree(tree, placements, semIndex, ti, placedOut)"] --> B{node type?} B -->|"And"| C["eval each child"] C --> D{worst result?} D -->|all satisfied| R1["'satisfied'"] D -->|any 'order'| R2["'order'"] D -->|any 'missing'| R3["'missing'"] B -->|"Or"| E["eval each child"] E --> F{best result?} F -->|any satisfied| R4["'satisfied'"] F -->|any 'order'| R5["'order'"] F -->|all 'missing'| R6["'missing'"] B -->|"leaf course ref"| G{"in placedOut?"} G -->|yes| R8["'satisfied'"] G -->|no| H{"in placements?"} H -->|no| R7["'missing'"] H -->|yes| I{"concurrent flag?"} I -->|yes: fi <= ti| R9a["'satisfied' (same sem ok)"] I -->|no: fi < ti| R9b["'satisfied' or 'order'"]
Worst-case propagates up And; best-case propagates up Or. "order" = placed but too late. "missing" = not in the plan at all. Placed-out courses are always satisfied.

Exported function

evalPrereqTree(tree, placements, semIndex, ti, placedOut?) → "satisfied" | "order" | "missing"
Walks the prerequisite tree recursively. For each leaf course reference ({ subject, number }), checks if it's placed and whether it's in a prior semester.
  • "satisfied": prereq is placed in an earlier semester (or same semester if concurrent: true, or placed out)
  • "order": prereq is placed but in the same or a later semester (ordering violation)
  • "missing": prereq is not placed in the plan at all
And nodes return the worst child result (missing > order > satisfied).
Or nodes return the best child result (satisfied > order > missing).
Returns: "satisfied" | "order" | "missing"
Parameters: tree = prereq token array, placements = {courseId→semId}, semIndex = {semId→ordinal}, ti = ordinal of course being checked, placedOut = Set of placed-out courseIds (defaults to empty)

Concurrent prerequisites

Some courses are marked concurrent: true on their leaf reference — the catalog phrase is "may be taken concurrently." For these, the check allows same-semester co-placement: fi <= ti instead of fi < ti. The concurrent flag is set by scrape-catalog.js when it sees "(may be taken concurrently)" in the prerequisite text.

How PlannerContext uses this

// PlannerContext.jsx — violation computation (simplified)
const violations = new Map();
for (const [courseId, semId] of Object.entries(placements)) {
  const course = courseMap[courseId];
  if (!course?.prereqs) continue;
  const semIdx = SEM_INDEX[semId] ?? 0;
  const result = evalPrereqTree(course.prereqs, placements, SEM_INDEX, semIdx);
  if (result !== 'satisfied') violations.set(courseId, { type: result });
}

This runs after every placement change. The resulting prereqViolations Map is read by CourseCard (warning icons) and RelationLines (draws red lines for violated edges).

Corequisite violations (not in this module)

Corequisite checking is handled inline in PlannerContext — a coreq violation occurs when the required course is not placed in the same semester as the course that requires it. The check is simpler: just look up if placements[coreqId] === placements[courseId].
