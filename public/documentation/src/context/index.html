context/ State bridge

Four React contexts that bridge adapter data, application state, i18n, and theming. ThemeContext handles CSS variable injection. InstitutionContext injects the adapter bundle. LanguageContext provides translation and locale. PlannerContext owns all mutable planner state.

Parent
src/
Provider nesting order
ThemeProvider → InstitutionProvider → LanguageProvider → PlannerProvider
Hooks exported
useTheme(), usePort(), useInstitution(), useLanguage(), usePlanner()

Children

context
InstitutionContext.jsx
Injects the adapter bundle into the React tree. Wrap root once with InstitutionProvider, then call usePort(IPortName) anywhere to read a port implementation.
context
LanguageContext.jsx
i18n layer. Provides t(key, vars) translation function and setLocale(). Loads 7 locale files at build time via Vite glob. Persists choice in localStorage.
context (hub)
PlannerContext.jsx
All mutable planner state: placements, cohort, drag-drop, undo/redo, multi-plan, violations, persistence, MCP sync. Every UI component reads from it via usePlanner().
context
ThemeContext.jsx
Reads theme from localStorage, injects ~100 CSS variables onto <html> at runtime. Cycle between themes without any component re-renders.

Provider nesting order

The four providers nest in exactly this order in App.jsx. The order is determined by dependency:

// src/App.jsx
<ThemeProvider storagePrefix={institutionAdapter.institution.storagePrefix}>
  <InstitutionProvider adapter={institutionAdapter}>
    <LanguageProvider>
      <PlannerProvider>
        <PlannerApp />
      </PlannerProvider>
    </LanguageProvider>
  </InstitutionProvider>
</ThemeProvider>
ProviderWhy it's where it is
ThemeProvider (outermost)Reads storagePrefix from the adapter object as a React prop — not via React context. Must be outermost so its CSS variables are on <html> before any child renders.
InstitutionProviderProvides usePort(). Must be above LanguageProvider and PlannerProvider because both call usePort(IInstitution) internally.
LanguageProviderCalls usePort(IInstitution) to read defaultLocale and storagePrefix. Must be above PlannerProvider in case planner UI ever needs t().
PlannerProvider (innermost of the four)Calls usePort() for calendar, courseCatalog, specialTerms, institution. Must be inside InstitutionProvider.

Most state comes from PlannerContext. Institution config comes from InstitutionContext. Translation from LanguageContext. Theme is pure CSS — components don't call useTheme() except Header (which has the theme switcher button).

No prop drilling

No component passes shared state down via props. Any component can read or mutate any state with one hook call. The trade-off: adding new shared state means editing PlannerContext.jsx, which is already large (~1,600 lines). Before adding state there, check whether it can live as local component state instead — if only one component needs it, keep it there.
