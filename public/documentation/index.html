nu-map

A zero-backend, single-page React degree planner for Northeastern University. Every piece of logic runs in the browser — no server, no database, no auth. Plans live in localStorage and export as JSON.

Architecture overview

The app uses a hexagonal (ports & adapters) architecture with a hard boundary between institution-specific config and the app core. All NU-specific values — semester types, NUPath codes, co-op rules, course catalog URL, disclaimers — live in src/adapters/northeastern/. The core is institution-agnostic. Swap one import in src/config.js and the planner reconfigures for any university.

Key design decisions

Hexagonal architecture

Institution-specific values are isolated behind JSDoc port contracts. The core is institution-agnostic. Adding a new school means writing one adapter folder and editing one import — nothing else changes. The same design makes individual ports easy to extend: adding a new semester type only touches calendar.js; adding a new gen-ed code only touches attributeSystem.js.

No backend, ever

Zero hosting cost, no migrations, no auth. Plans persist in localStorage and export as portable JSON files. All course data is scraped and bundled at build time — the app works offline after the first load.

React Context over Redux

All mutable state lives in PlannerContext. No action/reducer boilerplate. Any component reads or mutates any state with one usePlanner() call. LanguageContext and ThemeContext follow the same pattern for their narrower concerns.

Weight-based span arithmetic

Semester types carry a weight (fall/spring = 1.0, sumA/sumB = 0.5). Special term duration descriptors carry a matching weight. A term spans into the next semester slot when termWeight > semSlotWeight — no hardcoded duration checks anywhere in core logic.

CSS variables for theming

ThemeContext injects ~100 CSS custom properties onto <html> at runtime. All components reference var(--token) inline. Switching themes — or adding a new one — requires no component changes.

Fixed layout + CSS scale

Components are written at one canonical desktop scale. On smaller screens, App.jsx applies transform: scale(uiScale) so there is exactly one layout to maintain. isPhone and isMobile flags in PlannerContext handle the few cases that need a genuinely different presentation (e.g., phone-only course card compact mode).

Quick start

git clone https://github.com/nayugu/nu-map
cd nu-map
npm install
npm run dev              # Vite on :5173 + catalog-check-server on :3333

npm run data:scrape:write  # update catalog-courses.json from catalog.northeastern.edu
npm run data:patch:write   # apply YAML corrections from data/northeastern/patches/
npm run build              # production bundle → dist/
